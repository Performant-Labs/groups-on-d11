# PERF-1 baseline profiling — 2026-07-24

Baseline zero-load performance measurements for core anonymous pages, taken to
give future performance work a reference point. Closes issue #242, part of the
Performance epic (#241).

## Environment

| Field | Value |
|-------|-------|
| Target | `https://groups.performantlabs.com` (production demo on Uranus) |
| Auth | Anonymous only |
| Client | Playwright 1.49 / Chromium (headless) |
| Client host | Windows 11 workstation, home broadband |
| Timestamp (UTC) | 2026-07-24 |
| Runs | 3 cold + 5 warm per page |
| "Cold" | Fresh `chromium.launch()` + fresh `newContext()` each run (no HTTP cache, no cookies) |
| "Warm" | Single browser + context; one throwaway load to prime, then 5 recorded runs |
| Settle window | 2.5 s after `load` event to let LCP / CLS observers accumulate |

The script that produced these numbers lives at `scripts/perf/baseline.mjs` and
is re-runnable:

```bash
BASE_URL=https://groups.performantlabs.com \
RUNS_COLD=3 RUNS_WARM=5 \
node scripts/perf/baseline.mjs > baseline.json 2> baseline.log
```

## Metric definitions

| Metric | Source | Notes |
|--------|--------|-------|
| TTFB | `PerformanceNavigationTiming.responseStart − requestStart` on main document | Wire time only; excludes DNS/connect. |
| DCL | `domContentLoadedEventEnd − startTime` | End of DOM parse + deferred scripts. |
| Load | `loadEventEnd − startTime` | All subresources fetched. |
| LCP | `PerformanceObserver('largest-contentful-paint')`, last entry | Standard Core Web Vital. |
| CLS | `PerformanceObserver('layout-shift')`, sum of entries with `!hadRecentInput` | Standard Core Web Vital. |
| Bytes | Sum of `content-length` (fallback: response body length) across all responses | Decompressed body for gzipped responses lacking `content-length`. |
| Requests | Count of `response` events | Includes redirects and subresources. |
| FID / INP | — | Not measured — no scripted interaction. Anon-load-only baseline. |

Client-side network was a residential broadband connection; TTFB numbers
therefore include home-to-Uranus round-trip time and are not directly
comparable to the server-side p95 the SLA is defined against (see the
"Comparison to SLA" section below).

## Comparison to SLA

`docs/ops/sla.md` §1 sets anonymous-page targets of **p95 TTFB < 500 ms** and
**p99 TTFB < 1.5 s**. That target is measured at Uranus' Caddy proxy — a
server-side timing that excludes client-side network. Our client-side TTFB
p95 of ≤ 216 ms across every page includes the home-broadband RTT, so the
server-side number is meaningfully lower. **No page breaches the p95 anon SLA.**
The nearest ratio (`/group/1` warm at 216 ms client-side p95) still leaves the
target ~2.3× headroom before triggering the alert-worthy threshold.

## Observations

- **Cold vs warm is dominated by static-asset caching, not TTFB.** TTFB moves
  by < 25 ms between cold and warm (browser cache does not affect main-document
  wire time), but Load drops ~3× (e.g., `/` 1441 → 466 ms) and LCP drops ~5×
  (`/` 1216 → 252 ms) because CSS / JS / images come from disk cache. This is
  the expected shape for a Drupal render-cache-hot page — further gains would
  come from reducing subresource count or size, not from server tuning.
- **`/` cold p95 Load of 4037 ms is a single-run outlier.** One of three runs
  took 4.0 s; the other two took 1.40 and 1.44 s. p50 = 1441 ms. Ripe cause is
  a resource-hint contention or a font swap on the very first render. Worth
  spot-checking during PERF-2, not alertable on its own.
- **`/showcase` returns 404 on production.** The showcase module (#119) is in
  the repo but is not deployed to `groups.performantlabs.com` yet. Measurements
  above are the 404 page (7 requests, 157 KB) — kept in the table for
  completeness; the numbers are not representative of the actual showcase page
  and should be re-taken once the module ships.
- **CLS is 0.000 everywhere.** No layout-shift entries observed on any page.
  Either the pages genuinely have no async-inserted layout, or the 2.5 s
  settle window closes before slow assets (e.g., web fonts on cold reload)
  land — this is a candidate for PERF-2 to re-verify with a longer window and
  a throttled network profile.
- **`/group/1` is the heaviest page** at 527 KB / 14 requests warm, driven by
  member avatars and header imagery. It also has the slowest warm LCP (288 ms)
  and slowest warm Load (536 ms) — a plausible first target for PERF-3+.
- **FID / INP not measured.** No scripted interaction. Adding INP would
  require a per-page interaction script (button clicks, form focus). Recommend
  deferring to a subsequent story once we have a UI-heavy page worth probing.

future comparisons to re-measure against current conditions rather than
trusting stale numbers.
